### 1.1 Package offers (`5d49ead`, `25edb8b`)

Staff set a discount per sailing; the customer sees the old price struck
through and the new one beside it.

- `apps/packages/models.py`: `OfferType` choices, `offer_label`,
  `discount_type`, `discount_value`, `offer_ends_at`, plus `offer_is_live()`
  and `discount_on(subtotal)`.
- Migration `packages/0011_package_offer`.
- `apps/bookings/pricing.py`: the discount is applied inside
  `price_breakdown()`, **not** at the call sites. That is the whole point —
  quote, `Booking.reprice()` and the invoice all go through that one function,
  so there is no path by which a customer is quoted an offer and charged
  without it.
- The public package serializer publishes an `offer` object carrying the
  was-and-now prices, so the card does not recompute money in the browser.

**Trap:** the breakdown gained `subtotal`, `offer_label` and `discount` keys.
`restore_breakdown()` must read every one of them with a **default**, because
snapshots frozen before this feature do not carry them and those bookings are
still re-rendered on demand (invoice resend, regeneration after a redeploy). A
bare `snapshot["discount"]` 500s the invoice of every pre-feature booking.

### 1.2 Deposit floor published with the package (`170cdc6`)

### 1.3 Ship default adult fare (`9b2e968`)

### 1.4 Whole-cabin pricing (`894575b`) — the biggest one

A cabin is charged at its **full berth capacity** however many people take it,
less a configurable allowance per empty adult berth (the food an absent guest
would have eaten over the trip — flat per trip, not per night).

- `apps/ships/models.py`: `meal_allowance` (nullable) + a `sells_whole_cabins`
  property. Migrations `ships/0018_ship_meal_allowance` and
  `ships/0019_meal_allowance_optional`.
- `apps/bookings/pricing.py`:

```python
if package.ship.sells_whole_cabins:
    charged_adults = max(adult_count, room_type.max_adults)
    meal_allowance = package.ship.meal_allowance
else:
    charged_adults = adult_count
    meal_allowance = ZERO
empty_berths = charged_adults - adult_count
subtotal = max(ZERO, room_type.base_price + adults_subtotal + kids_subtotal
               + foreigner_subtotal - empty_berth_discount)
discount = package.discount_on(subtotal)
```

**`meal_allowance` is NULLABLE and null means "sell per head".** This is not
tidiness — it is what stops the feature silently raising every live price the
moment it ships. Defaulting it on broke 140 tests here and would have changed
real quoted prices on a live site. Keep it opt-in.

**Note the floor is applied BEFORE the discount:** an allowance larger than the
cabin must give a free cabin, never a negative one, and a percentage off a
negative number hands money back.

**Watch out when testing:** with a low test price, `(berths × price) −
allowance` can floor to **৳0**, and a ৳0 booking can never be paid
(`initiate_payment` refuses when nothing is due) while still holding its cabin.
Price test packages so the total clears ৳10, or turn the ship's whole-cabin
setting off while testing.

### 2.6 Customer-facing error messages (`12666dd`) — port this

Every public error path rendered raw DRF output, and **two of the three shapes
the booking API actually returns did not survive the trip**. Verified against
the live API, not guessed:

| API returns | Customer saw |
|---|---|
| `{"rooms":{"0":{"adult_count":"…at most 2 adults."}}}` | **an empty toast** |
| `{"rooms":[{"room_id":["Invalid pk \"99999\" …"]}]}` | **`[object Object]`** |
| `{"rooms":["This field is required."]}` | "This field is required." |

The first is the likeliest mistake a real customer makes — four people in a
two-berth cabin — and it told them nothing at all.

- `src/lib/api/client.ts`: `toApiError` now walks the payload to its leaves and
  keys each message by a dotted path (`rooms.0.adult_count`). The old loop only
  understood arrays of strings: an object value was skipped, leaving
  `fieldErrors` as `{}` — **which is truthy**, so callers rendered an empty
  string. It now returns `undefined` when there is genuinely nothing to say.
- `src/lib/errors.ts` (new): `customerError(err, fallback, cabins)`.
  Sentences our own validation wrote pass through untouched; only DRF's stock
  phrasing is rewritten. `detail` wins on 4xx, where we write it; status
  wording wins on 429 and 5xx, where the platform does and says things like
  "Request was throttled."
  The `cabins` argument exists because errors are keyed by cabin index whether
  the booking holds one cabin or four — without it a single-cabin booking reads
  "Cabin 1: …" and a four-cabin one never says which.
- Wired into all five public paths: creating a booking, the live fare quote,
  the payment redirect, paying later from the confirmation page, and the
  contact form.

## 3. Frontend — staff dashboard

### 3.1 Bangla / English (the largest piece)

Commits `0f37a93`, `320a5aa`, `f352fb5`, `d8d9b41`, `3b7d13d`, `df62366`,
`7cc43ca`, `6f2c520`.

**Staff dashboard only. The customer site stays English.**

Three new files, no i18n library:

| File | Holds |
|---|---|
| `src/lib/i18n/index.tsx` | `LanguageProvider`, `useLanguage()`, `useT()`, and — for plain functions that are not components — `translate()`, `tr()`, `currentLang()` |
| `src/lib/i18n/strings.ts` | one flat `STRINGS` object; `export type StringKey = keyof typeof STRINGS` |
| `src/lib/i18n/format.ts` | `money()`, `num()`, `date()`, `dateTime()`, `percent()` over `Intl` with `bn-BD` |

The provider wraps the layout in the route definition, so every staff page is
inside it without each one remembering to be. `staff_.login.tsx` needs its own
provider because it sits outside the staff layout.

**Traps, all of which cost time here:**

1. **`STRINGS` is `as const`**, so without an explicit annotation the inferred
   type is the one literal that happened to be read first:
   ```ts
   let text: string = entry ? (entry[lang] ?? entry.en) : key;
   ```
2. **Numbers and dates must go through the formatters too.** Bangla labels
   wrapped around English digits read as half-finished. `৳ ২০,০০০.০০`, not
   `৳ 20,000.00`.
3. **`errorText()` in `components/staff/ui.tsx` is a plain function**, called
   from event handlers, so it cannot use a hook. That is why `tr()` /
   `currentLang()` exist — they read the stored language directly.
4. **Labels in module-level arrays are easy to miss.** Filter chips, payout
   methods and similar live in `const FILTERS = [...]` outside JSX, so a scan
   of the JSX will not find them. They were still English after the first pass.
5. **`subtitle="..."` → `subtitle={t("...")}`** — the missing braces bug
   recurred on four pages.
6. **Two things stay English on purpose:** the booking CSV's header row (so the
   file opens the same way in every spreadsheet it is mailed to) and the DRF
   sentences `errorText()` matches against (they are what the server sends).

The language switch lives on **Settings**, not the sidebar — a preference set
once belongs with the other settings. It applies on click with no Save button,
and its toast is written out in both languages because `t()` still holds the
old language while the click is handled.

The "Signed in as <user>" line was removed from the sidebar; Settings › Account
already says who is signed in.

### 3.6 Pointer cursors (`8f9d9c4`) — one line, 170 buttons

**Tailwind v4's Preflight gives buttons `cursor: default`; v3 gave them

`src/styles.css` `@layer base` rather than as a class on each element — which

```css
[role="button"]:not([aria-disabled="true"]),

```

Disabled buttons are excluded: a pointer on something inert is a small lie.

## 4. ⚠️ Carry this warning across: nothing runs the cron

Found by audit here on 2026-09-17 and **still open on this site**. The sister
site is a copy, so it has the same hole.

`render.yaml` has no cron block, `railway.json` never had one despite a
docstring that claimed it did, and no scheduler package is installed.
`DEPLOYMENT.md` documents the schedule as REQUIRED; nobody wired it up.

**What that costs:** a customer who starts checkout and closes the tab leaves a
PENDING payment. `reconcile_pending_payments` never runs, so it is never closed
with the gateway; `expire_stale_bookings` correctly refuses to release a cabin
while a gateway session is open on it. **That cabin never returns to
inventory.** Registering the IPN URL does not fix it — `mark_payment_closed`
only changes the Payment row; freeing the cabin is `expire_stale_bookings`,
which is cron-only.

Also not running: balance-due reminders, retries of failed invoice emails,
closing sailed bookings, and the JWT blacklist sweep.

**Fix:** `run_payment_jobs --quick` every ~10 minutes and the full set daily.
On a VPS that is two crontab lines. On Render's free tier it needs a
token-protected HTTP endpoint hit by a free scheduler (cron-job.org) — which
has the side benefit of stopping the free instance sleeping after 15 minutes,
currently costing real visitors a ~50 second cold start.
